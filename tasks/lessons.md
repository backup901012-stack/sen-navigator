## 2026-06-13 [事實準確] CAS/CAC 混淆 + 管理機構錯（官方名詞未逐一查證）

**情境**：評估與分級頁「機制 C」一直寫「衞生署 兒童體能智力測驗服務（CAS）」，
並把各區「測驗中心」都當作 CAS、全部當衞生署管理。老闆指正。

**官方真相（多源查證：HA Content_ID=282515、官方 PDF dkhcac@ha.org.hk、dhcas.gov.hk、data.gov.hk）**：
- 「服務」= Child Assessment **Service**（CAS）；「中心」= Child Assessment **Centre**（CAC）——兩者不同層面，不能混用。
- 全港 **8 間 CAC**：**7 間衞生署**（中九龍／尤德夫人觀塘／尤德夫人沙田／屯門／下葵涌／粉嶺／牛頭角）+ **1 間醫院管理局**營辦（**大口環根德公爵夫人兒童醫院**，港島西聯網，email dkhcac@ha.org.hk、電話 2974 0331）。
- 「大口環」醫院官方是「**根德公爵夫人**兒童醫院」（Duchess of Kent），不是「尤德夫人」；尤德夫人是衞生署觀塘／沙田兩間中心，兩者是不同實體（老闆口述把兩者混了，已用官方名）。

**誤區**：把官方專有名詞（Service vs Centre、縮寫 CAS vs CAC）、管理機構（DH vs HA）當「常識」直接寫，沒有逐一對官方核實。香港 SEN 領域官方名詞精細，差一個字（服務/中心）或一個機構（衞生署/醫管局）就是事實錯誤。

**規則**：本網站任何官方服務／機構／單位名稱、英文縮寫、管理機構、單位數目 →
**必逐一對官方來源查證**（HA / DH / EDB / SWD 官網或 data.gov.hk），不可憑印象。
縮寫要分清「服務（Service）」與「中心／單位（Centre）」層面；列「全部由 X 管理」前必確認有無例外單位。

**升級狀態**：首次（本專案 lessons 首條）。對應 commit 6f64b6e（v1.1.1 → 實為 web v1.9.1）。

## 2026-06-13 [內容/心理輔導] 同理 ≠ 同情（過度同情對 SEN 家庭是壓力）

**情境**：寫公眾教育「認識・同理」頁時，用了「筋疲力盡的家長」「想對每一位說的話」等溫情喊話。
老闆指出：心理輔導中同理（empathy）不同於同情（sympathy）；SEN 家長與孩子對過度同情會有壓力，
覺得是「非同路人旁觀者的說教評論」。

**規則**：寫 SEN／弱勢／照顧者相關文案 →
- 用**同理**（平等、與你同在、不評價、賦能）而非**同情**（由上而下、憐憫、「好慘」、神化、說教）
- 避免：「好可憐」「好偉大／堅強」「不如試吓…」未經邀請的建議、過度溫情、把對象當「不幸」
- 核心：SEN 家庭要的是被當成「平常」對待，不是被同情或讚嘆
- 依據：Brené Brown empathy vs sympathy；同理四要素（換位、不批判、辨識情緒、表達理解）

**升級狀態**：首次。對應 /understanding 頁「同理，不是同情」section（v1.10.0）。

## 2026-06-13 [事實準確] 香港特殊教育官方知識（已查證、可重用）

- **特殊學校非「校網分區派位」**：按殘疾類別/程度/評估建議/家長意願/學額，由 EDB 統一安排；
  入學是經 EDB 專業評估→建議→家長同意→轉介，**不是家長自行報名**。
- **雙軌制**：輕度 SEN→主流學校融合教育（全校參與模式）；較嚴重/多重殘疾→特殊學校。
- **62 所特殊學校**（EDB 2023/24）：智障 43（輕/中/嚴重）、肢障 7、群育 8、視障 2、聽障 1、醫院 1。
- **常見訓練方法**（HKU PAAC）：ABA、DTT、TEACCH、PECS、Floor Time、Social Stories、Sensory Integration；
  早期介入+個別化+家人參與為共識；食療/藥物/輔助療法欠科學證據、勿盲信。
- 對應 /special-schools、/training-methods（v1.11.0）。

## 2026-06-19 [內容/事實] TSP 是「輪候期中轉服務」、不應放在服務配對作推薦

**情境**：服務配對（MatchTool）會對走 gov/both 軌的家長推一張「申領學習訓練津貼 (TSP)」、tag「經濟支援」。老闆指正：TSP 不能放在這個配對頁。

**老闆原話**：「TSP 等於等待政府服務的中轉服務」；「需要 3 個月的經濟審查申報，然後社署再提供去 E 位或 S 位，該機構評估後再做免課程費用的 3T 訓練」。

**官方查證（社署 swd.gov.hk/tc/pubsvc/rehab/cat_serpresch/tsp/）**：
- TSP =「為輪候資助學前康復服務的兒童提供學習訓練津貼」（俗稱 T 位），是**輪候期間的中轉／過渡**津貼。
- 對象：6 歲以下、已在中央轉介系統輪候、未領取資助服務。
- 入息審查：輪候 **EETC／兼收（E 位）需家庭入息審查**（≤住戶入息中位數 75%）；輪候 **SCCC（S 位）自 2017-10 起不設入息審查**。
- 流程：經濟審查 → 社署編配 E 位／S 位 → 機構評估 → 才獲免費（3T）訓練。

**誤區**：把一個「綁定特定資格＋多步申請流程」的中轉服務，當成人人走 gov 軌就該收到的即時「配對建議」，且誤 tag 為「經濟支援」。

**規則**：服務「配對」頁只放可即時對應需要的服務方向；像 TSP 這種有資格門檻＋固定申請流程的中轉/過渡服務，應放在 /journey 申請流程或 /directory 資源目錄，並準確描述為「輪候期過渡服務」。

**處置**：移除 MatchTool 的 reco-tsp 區塊（v1.14.1）；TSP 在 /journey、/directory、/faq 仍以「過渡/輪候期支援」正確框架保留。

**升級狀態**：首次。對應 commit（v1.14.1）。

## 2026-07-07 [手機驗證/UX] 「揀身份卡後去錯/空白」真因＝換步冇捲返頂 + 驗證要用 Safari 引擎

**情境**：用戶回報「手機開站，揀身份卡後有反應但去錯/空白，沒連到學校資料」。

**驗證方法（有效、可重用）**：
- 用 **Playwright WebKit（真 Safari 引擎）+ Chromium 兩者**、`devices["iPhone 13"]`（mobile viewport + `hasTouch` + 真 `tap()`）跑，唔淨係 Chromium——真 iPhone 用 WebKit。
- 逐層量測：EntryGate 揀卡 → 攞路線 → 學校連結導航（URL 有變？學校資料載入？）；`page.on("response")` 抓 4xx/5xx；`getBoundingClientRect()` 量元素喺唔喺視窗內。
- 對照組：同一 e2e 跑 live 舊版，分清「本次回歸」定「既有問題」（本次 e2e 25/26，唯一 FAIL＝既有 TSP 過時測試、live 一致，非我回歸）。

**真因（實測）**：EntryGate 兩步式 modal，step1 五張卡在螢幕下方、用戶要**捲到底**先撳到「攞我嘅路線」；換到 step2 時 `overflow-y-auto` 容器**沿用舊 scrollTop**（實測 step2 標題 top=-123），一入見中段、見唔到頂部標題同路線第一步 → 感覺「揀完去錯/搵唔到學校連結」。**新舊版皆有**、純功能其實正常（導航照跑）。

**誤區**：① 一開始以為 CSS `grid place-items-center` 垂直置中裁走頂部——改 `flex + m-auto` 後**實測 top 仍 = -123、根本冇變**（差啲把無效改動當修復）。真兇係**捲動位置**唔係置中。② 模擬全過就想講「冇 bug」——但用戶真機真實經歷唔可以憑模擬否定；最可能係**舊快取**（本專案部署曾多次 failure、v1.24.0 push 部署都 failed 過、靠手動 re-trigger 上線）。

**規則**：
1. 多步式 modal / 覆蓋層，**每次換步或重開都要把捲動容器 `scrollTo(0,0)`**（`useEffect([open,step])` + `ref`），唔好靠 CSS 置中。
2. 手機 bug 驗證**一定用 WebKit（Safari 引擎）**，唔淨係 Chromium；用真 `tap()` + mobile device descriptor。
3. 改咗 CSS 唔好靠腦補「應該修好」，**實測量度前後數值**（`getBoundingClientRect`），無變化＝無效改動、唔可以當修復（honest-progress）。
4. 模擬重現唔到用戶 bug 時，**查部署新鮮度 + 提醒用戶清快取/無痕測**，唔好一句「冇 bug」否定用戶。

**處置**：v1.24.1（commit 823bcc7）加 `scrollRef` + `useEffect([open,step]) scrollTo(0,0)`；`close()` 順手重置 `body.overflow`；版面改頂對齊。線上實測 step2 標題 top=-123 → **top=40（可見）**、導航照常、0 錯誤。Codex review 無 P0/P1。

**升級狀態**：首次。對應 commit 823bcc7（v1.24.1）。
